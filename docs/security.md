# 安全与加固

> 这套东西本质上是**把一台机器的桌面暴露到网络上**。做对了很安全，做错了等于把家门钥匙挂在门口。

## 一、暴露面

| 组件 | 默认绑定 | 是否对公网 |
| --- | --- | --- |
| x11vnc（5900） | 127.0.0.1 | ❌ 不要 |
| websockify（6080） | 127.0.0.1 | ❌ 由 nginx 转发 |
| clipbridge（8137） | 127.0.0.1 | ❌ 由 nginx 的 `/clip/` 转发 |
| nginx（443/自定义端口） | 0.0.0.0 | ✅ 唯一入口 |

**VNC 本身没有强认证**：它只有一个 8 位口令，且默认不加密。所以 x11vnc 必须用 `-localhost` 只监听回环，由网关做认证。

## 二、认证与传输

1. **TLS 必须有**。既保护口令，也保护画面与剪贴板内容；浏览器的 `navigator.clipboard` 也只在安全上下文可用。
2. **Basic Auth 是最低门槛**，够用于家庭。要点：
   - `htpasswd -B` 用 bcrypt；
   - 口令长度 ≥ 12，别复用；
   - 如果多人使用，每人一个账号，方便单独吊销。
3. **更强的方案**（按需）：
   - 网关换成 OIDC / Authelia（前置 SSO，支持 2FA）；
   - 或只允许 Tailscale/WireGuard 网段访问（`allow 100.64.0.0/10; deny all;`），公网完全不暴露；
   - Cloudflare Tunnel + Access：不开放任何入站端口。

## 三、加固清单

```nginx
# 只允许特定网段（可选）
allow 192.168.1.0/24;
deny all;

# 限制暴力破解
limit_req_zone $binary_remote_addr zone=wb:10m rate=10r/m;
server {
    location / { limit_req zone=wb burst=20 nodelay; }
}
```

```bash
# fail2ban：拦 Basic Auth 失败
sudo apt install fail2ban
```

- 关闭不必要的端口；`ss -lntp` 定期自查；
- 系统与 `nginx`、`x11vnc` 保持更新；
- 应用以**普通用户**运行（systemd `User=`），不要用 root；
- 只给该用户必要的目录权限；
- 开启 `ufw`/`firewalld`，默认拒绝入站。

## 四、剪贴板桥的风险

桥的能力等价于"能读写该用户 X 剪贴板的人"，具体是：

- 能读到你在**远端**复制的任何内容（密码、验证码、私密文本）；
- 能把内容**写进**远端剪贴板，若同时能注入按键，就有可能触发粘贴。

因此：

- 剪贴板桥**只能**通过已认证的同源路径访问（本项目默认如此），不要把 8137 直接映射到公网；
- 不要在远端剪贴板里长期停留敏感内容；
- 上传的图片会落在 `CLIP_UPLOAD_DIR`，定期清理，且该目录不要被网关静态暴露。

## 五、会话与数据

- 远端会话长期在线，**拿到入口就等于拿到桌面**：这是设计目标，也是最大风险。请务必：
  - 网关强制 HTTPS，禁止 HTTP 明文；
  - 定期轮换口令；
  - 出差/公共网络下不要在浏览器里保存口令。
- 客户端把 Basic 口令存在 `config.json`（明文）。若设备可能被他人使用，请改用"每次输入"或系统级凭据加密。
- 备份包含用户数据（会话记录、资料库）。备份文件请加密存放。

## 六、多用户

本项目默认是**单用户单会话**。多人使用请：

- 每人一个 Linux 用户 + 独立 `DISPLAY`（如 `:98`、`:99`）+ 独立端口 + 独立网关路径；
- 或改用虚拟机/容器做隔离（此时隔离性正是虚拟机的主场）。

## 七、事故响应

如果怀疑口令泄漏：

```bash
sudo htpasswd -D /etc/nginx/wb.htpasswd 用户名     # 立即吊销
sudo systemctl restart wbdesktop                    # 强制断开所有会话
# 检查异常登录
sudo grep -i "basic" /var/log/nginx/access.log | tail -50
```

如果主机被入侵，仅改口令不够：桌面会话里保存着登录态与文件，应按"主机失陷"处理。
